# FieldMind AI — LangGraph Multi-Agent Architecture & Intake State

This document specifies the LangGraph multi-agent workflow architecture, central state schema, state lifecycle transitions, error handling mechanisms, and persistent checkpointing.

---

## 1. Multi-Agent Workflow Overview

Customer service requests enter through multiple channels (WhatsApp voice notes, web portal text, mobile app). The intake layer normalizes the request into a shared LangGraph state container (`FieldMindWorkflowState`) and orchestrates processing across modular agent nodes.

```
Customer Request (Text or Audio)
               ↓
     Initial Intake State
               ↓
          Input Type
           ↙       ↘
     [TEXT]         [VOICE]
        ↓              ↓
    Text Node      Voice Node
        │              ↓
        │         Whisper API
        │         Transcription
        │              ↓
        └──────→ LangGraph ←──────┘
                   ↓
            State Transition
                   ↓
            Validation / Error Check
                   ↓
         Downstream AI Processing
          (Intent Diagnostics)
                   ↓
         Persistent Checkpoint
           (Memory / PostgreSQL)
```

## 2. Intake State Schema (`FieldMindWorkflowState`)

Defined in `backend/app/agents/graph/state.py`.

### Primary State Fields

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `job_id` | `str` | **Required.** Unique UUID identifying the service request thread. |
| `customer_id` | `str \| None` | Identifier of the customer if authenticated. |
| `customer_info` | `CustomerInfo \| dict` | Preserved contact details (`name`, `phone`, `email`). |
| `input_type` | `InputType` (`TEXT` \| `VOICE`) | Modality of the request. Auto-detected if omitted. |
| `request_text` | `str \| None` | Raw natural-language text submitted by the customer. |
| `user_prompt` | `str \| None` | Standardized text query for downstream AI processing. |
| `audio_ref` | `str \| None` | Persisted media reference / storage key for audio. |
| `audio_transcript` | `str \| None` | Text transcript generated by Whisper. |
| `voice_state` | `VoiceProcessingState \| None` | Structured sub-state tracking audio processing. |
| `status` | `IntakeStatus` | Current lifecycle state of the request. |
| `current_step` | `str` | Tracking label for the active node in execution. |
| `errors` | `list[str]` | Accumulated list of workflow failure diagnostics. |
| `metadata` | `dict[str, Any]` | Extensible context (locale, channels, coordinates). |

### `VoiceProcessingState` Sub-State

| Sub-field | Type | Description |
| :--- | :--- | :--- |
| `status` | `VoiceProcessingStatus` | `PENDING`, `INITIALIZED`, `TRANSCRIBING`, `TRANSCRIBED`, `FAILED`. |
| `media_ref` | `str` | Reference URI / path of the audio file. |
| `media_format` | `str \| None` | Audio file extension/encoding (`ogg`, `mp3`, `wav`, `m4a`). |
| `duration_seconds`| `float \| None` | Audio recording duration. |
| `transcription` | `str \| None` | Transcribed audio output. |
| `word_confidence`| `float \| None` | Whisper model word accuracy confidence score. |
| `error_message` | `str \| None` | Captured error details if transcription fails. |

## 3. Intake State Transitions & Lifecycle

1. **Initialization (`START` ➔ `initial_router`)**:
   - `create_initial_intake_state`: Validates `job_id`, determines `input_type` (`TEXT` or `VOICE`), initializes `status = INITIALIZED`.
   - If invalid input: records error in `errors`, sets `status = FAILED`, routes to `workflow_failure`.
2. **Text Processing (`initial_router` ➔ `process_text`)**:
   - Validates that `request_text` is non-empty and within bounds (3 to 4,000 characters).
   - Normalizes text into `user_prompt`.
   - Sets `status = READY_FOR_DIAGNOSTICS`, `current_step = "TEXT_INTAKE_PROCESSED"`.
3. **Voice Processing (`initial_router` ➔ `initialize_voice` ➔ `transcribe_voice`)**:
   - `initialize_voice`: Format-checks audio extension (`.ogg`, `.mp3`, `.wav`, `.m4a`), builds `voice_state`.
   - `transcribe_voice`: Calls `WhisperClient`. On success, updates `audio_transcript`, sets `user_prompt`, transitions to `READY_FOR_DIAGNOSTICS`.
4. **Intent Handoff (`intent_handoff` ➔ `END`)**:
   - Verifies transcript / text is ready for downstream LLM intent diagnostic parsing.
5. **Workflow Failure (`workflow_failure` ➔ `END`)**:
   - Terminal error state capturing all validation or engine failures safely without unhandled exceptions.

## 4. Checkpoint Persistence & State Recovery

Defined in `backend/app/agents/graph/checkpoints.py`.

- **Thread Association**: Checkpoints are stored using key `thread_id = f"job-{job_id}"`.
- **In-Memory Checkpointing**: `get_memory_checkpointer()` (used in automated testing and transient pipelines).
- **PostgreSQL Checkpointing**: `PostgresCheckpointerConfig` connects with `settings.DATABASE_URL` against the SRD checkpoint tables (`checkpoints`, `checkpoint_blobs`, `checkpoint_writes`). Gracefully falls back to MemorySaver if PostgreSQL is unreachable.
- **State Recovery**:
  ```python
  from app.agents.graph.checkpoints import recover_workflow_state

  # Recovers state dictionary by thread ID
  saved_state = recover_workflow_state("job-12345")
  ```
